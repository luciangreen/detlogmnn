    How queries run

    Each query runs on the faster of two exact routes. The C route is pl2detlog's native tier: the analysis of its Prolog → Detlog → C export, compiled to JavaScript. It applies where the type contract holds (ground inputs, fresh outputs). It runs without runtime checks unless Runtime checks is on; a query outside the contract is then caught on its first run, when the C and MNN routes disagree, and Prolog decides. The MNN route is the proved Detlog MNN rewrite. The first run times both, and plain Prolog too, checks that they agree, and keeps the fastest: where the determinism rewrites make a query slower, Prolog runs it.

    Prolog runs what the conversion can't keep exact: conversion errors, programs that assert or retract, anything the round trip back to Prolog reports as lost, and any error, so errors are always Prolog's own.

    Point 1: a query with an output already given, like label([2,3], even(3)), is run as label([2,3], R), R = even(3): compute, then unify. This is used only where the output is proved steadfast, and here gives false, as Prolog does.

    time(Goal) reports inferences, time and the route used.
